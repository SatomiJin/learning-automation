Automation code cần dễ đọc như tài liệu nghiệp vụ nhỏ. File test nên cho reviewer thấy flow chính, Page Object giữ locator/action, helper xử lý data chung và assertion nên kiểm tra đúng expected result thay vì chỉ nhìn toast.

TypeScript order-creation.spec.ts 
test("should create order successfully when required fields are valid", async ({ page, request }) => {
  // Arrange
  const orderData = buildOrderData();

  // Act
  await orderPage.goto();
  await orderPage.create(orderData);

  // Assert
  await expect(orderPage.getOrderRow(orderData.orderCode)).toContainText("New");
});
✅
Tên file dùng *.spec.ts, Page Object dùng PascalCase, helper dùng camelCase, test title mô tả hành vi mong đợi và điều kiện xảy ra.

Checklist test-case-workflow.txt 
1. Hiểu user action, input và expected result
2. Phân loại smoke/regression/negative/e2e
3. Chọn setup data bằng UI hoặc API
4. Viết skeleton Arrange -> Act -> Assert
5. Chạy headed, debug, headless
6. Review locator, data uniqueness, assertion và secret
⚠️
Một test pass local một lần chưa đủ. Nên chạy lại nhiều lần, chạy headless và chạy cùng các file liên quan để phát hiện shared data hoặc timing issue.

Lỗi Người Mới Hay Gặp Và Cách Sửa
missing await · strict mode violation · weak assertion · test dependency · waitForTimeout
▼
Debug từ nguyên nhân thật

Các lỗi phổ biến nhất là quên await, locator match nhiều element, assertion chỉ nhìn toast, test phụ thuộc thứ tự, data bị trùng khi chạy song song và lạm dụng wait cứng. Sửa đúng nguyên nhân sẽ giúp suite bền hơn retry.

TypeScript common-fixes.ts 
// Thiếu await
await page.getByRole("button", { name: "Save" }).click();

// Locator match nhiều element
const row = page.locator("tr").filter({ hasText: orderCode });
await row.getByRole("button", { name: "Detail" }).click();

// Data unique khi chạy parallel
const customerCode = `CUSTOMER_${test.info().workerIndex}_${Date.now()}`;

// Wait theo trạng thái thật
await expect(page.getByText("Created successfully")).toBeVisible();
TypeScript strict-mode-violation.ts 
// Dễ lỗi: trên trang có nhiều nút Save
await page.getByText("Save").click();

// Tốt hơn: dùng role + accessible name
await page.getByRole("button", { name: "Save" }).click();

// Nếu vẫn có nhiều nút Save, khoanh vùng trong form/modal/row
const orderForm = page.getByTestId("order-form");
await orderForm.getByRole("button", { name: "Save" }).click();

// Với table, tìm row theo business key rồi mới click action trong row đó
const row = page.getByRole("row", { name: /ORDER001/ });
await row.getByRole("button", { name: "Detail" }).click();

// Chỉ dùng first()/nth() khi UI thật sự không có định danh tốt hơn
await page.getByRole("button", { name: "Save" }).first().click();
💡
Checklist khi gặp Strict mode violation: locator có quá chung không, có thể scope bằng form/modal/row không, có dùng được role/name/label không, hoặc có nên xin dev thêm data-testid không.

Flaky test xử lý sao?
- Xem trace, screenshot, network và console
- Kiểm tra locator có unique không
- Kiểm tra wait có dựa trên trạng thái thật không
- Kiểm tra data có bị shared/collision không
- Phân biệt lỗi môi trường và lỗi product

- Setup nhanh hơn
- Verify sâu hơn
- Giảm thao tác UI không cần thiết
- Test ổn định hơn khi flow dài
